koa洋葱模型
1. `index` 的作用是什么？
   用于记录当前执行的中间件索引，初始值为 -1。
2. `() => dispatch(i+1)` 就是我们写的 `next()` 吗？
   是的，`next()` 是一个函数，用于调用下一个中间件。
3. 为什么要包一层 `Promise.resolve`？
   为了处理异步中间件，确保每个中间件都能正确执行。
4. 如果某个中间件不写 `await next()`，会发生什么？
   如果某个中间件不写 `await next()`，那么它就会直接返回，不会调用下一个中间件。

1. `app.callback()` 对应原生 http 服务的回调，Koa 源码也是这个结构，看懂了吗？
   是的，`app.callback()` 是 Koa 应用的入口，它返回一个函数，用于创建 http 服务。
2. ctx 在这里只放了 req、res；真实 Koa 的 ctx 多了什么？
   多了其他属性，比如 `body`、`status` 等。
3. 错误在哪里捕获？这个捕获能抓到 Promise 里面裸抛、没有 await 的异常吗？
   是的，`app.callback()` 里面捕获了所有异常，包括 Promise 里面裸抛的异常。
   没有 await 的异常，因为 Koa 中的中间件都是异步的，不会直接抛出异常。

   1. 为什么耗时要在 `await next()` 之后打印？
   因为 `await next()` 是异步的，`start` 是在 `await next()` 之前调用的，所以 `cost` 是 `next()` 执行时间。
2. 如果我把计时写在 next 后面，start 放在 next () 里面，结果会怎么样？
   如果把计时写在 next 后面，start 放在 next () 里面，结果会是 `cost` 是 `next()` 执行时间，而不是 `await next()` 执行时间。
3. 能不能在这个日志中间件拿到响应状态码？怎么拿？
   可以，在 `await next()` 之后，`ctx.res.statusCode` 就是响应状态码。 200 成功
   400 请求参数错误
   500 服务器错误


1. 路由本质是不是也是一个中间件？匹配到路径执行 handler，匹配不到执行 next ()？
   是的，路由中间件是一个中间件，用于处理路由匹配。

2. koa-router 比这个多了什么？（动态参数 /:id、正则、路由前缀）
   koa-router 多了动态参数、正则、路由前缀等功能。
3. 如果注册多个路由中间件，洋葱顺序怎么跑？
   从内到外，先执行路由中间件，再执行日志中间件，最后执行错误处理中间件。
